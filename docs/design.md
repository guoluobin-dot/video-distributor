# 视频分发工具 · 设计文档

> 本文记录工具的模型、关键规则与各版本变更。面向想了解实现或参与改进的人。

---

## 1. 一句话需求

选好一个**目标父文件夹**，往工具里投放一堆视频/图片，工具按你设定的「每个日期放几个、日期隔几天」自动分成多个 `MM-DD未分发` 文件夹。

举例：投放 50 个视频，设置 8号15个、10号15个、12号20个 → 生成：

```
目标父文件夹/
  09-08未分发/ (15个)
  09-10未分发/ (15个)
  09-12未分发/ (20个)
```

---

## 2. 使用流程

1. 选「分发位置」文件夹（即输出父文件夹），路径会被记住
2. 设定规则：起始日期（默认今天）/ 每组数量 / 间隔天数（`0`=每天连续，`1`=隔一天）
3. 投放素材：拖入文件或文件夹（含子文件夹），自动过滤非视频/图片，显示总数
4. 自动生成计划表，表格仍可逐行改日期与数量
5. 点【预览分配】确认每个文件夹会分到哪几个文件
6. 点【确认执行】**移动**文件（非复制），显示进度条，完成后提示并可打开目标文件夹
7. 日志 `distribute_log_时间.csv` 可追溯、可撤回

---

## 3. 关键规则

| 编号 | 规则 |
| --- | --- |
| R-01 | 日期格式 `MM-DD未分发`，月日补零（`09-08未分发`）；日期递增 = 起始日期 + n×间隔天数 |
| R-02 | 排序用自然排序（`natsort`），key = `所在子文件夹名 + 文件名`，即「先文件夹、再视频1视频2」 |
| R-03 | 分配顺序：按排序后队列依次切分，第 1 组的 N 个给第 1 个日期，依此类推 |
| R-04 | 余量处理：计划总量 < 素材数 → 提示并自动多建一组装剩下；计划总量 > 素材数 → 最后一组取剩下并警告 |
| R-05 | 支持格式见 README「支持的格式」 |
| R-06 | 只做移动，不留副本；执行前强制预览确认；同名日期文件夹直接合并 |
| R-07 | 素材来源文件夹**只引用路径**，不复制、不搬走任何文件 |

## 4. 两级分配模型（均分页）

均分页的核心是一个两层结构：

```
素材（拖入的文件夹，只引用不搬走）         目标（拖入的文件夹，任意位置）
   D:\素材A   8个                                E:\渠道A
   E:\素材B   4个     ── 均分/自定义数量 ──▶     F:\渠道B   每个目标内部
   F:\混剪素材 3个      （12个 → 5/4/3）          G:\渠道C
                                                    │
                                                    └─ 内部完全沿用原逻辑：
                                                       从[日期]开始 每组[N]个 间隔[K]天
                                                       → MM-DD未分发
                                                       → 文件夹名+视频/图片+序号 改名
                                                       → 写日志，可撤回
```

- **外层**：素材 → 每个指定目标文件夹。`🌊均分`（平均分，余数给靠前的）或 `✏️自定义数量`（双击表格逐个改）
- **内层**：每个目标内部，用和「按日期分发」页**同一组**数值切成 `MM-DD未分发`

设计要点：

- 素材数 < 目标数时，按 `1/1/0` 分配，0 数量的目标在执行时被跳过（`_clean_targets` 过滤）
- 目标数量合计 < 素材数时，日志区明确提示「多出的 N 个没地方放」
- 加新目标时会先给一份覆盖全部素材的基准分配，再由用户改成自定义
- 执行/撤回后自动重新统计各来源还剩多少素材

## 5. 配乐（无 LLM）

**功能**：给 `MM-DD未分发` 文件夹里的视频换 BGM；可选按命名库 TXT 改名。原片备份可撤回。

**流程**：

1. 从音乐库随机不重复分配（离线）
2. 可选改名（默认关）：从命名库 TXT（每行一个命名，UTF-8/UTF-8-BOM/GBK）随机不重复取名；不勾则只换音轨、保留原文件名
3. 转码：ffmpeg `-c:v copy` 视频流直拷 + AAC 音频重编码，`DUB_WORKERS` 路并发（默认 4）
4. 已配乐视频（`dubbed_live_set`）本轮自动跳过
5. 原片备份到 `.配乐原片备份_*`，可随撤回一起还原

命名库约定：`命名库/` 目录，TXT 每行一个命名；一轮用完可复用。`load_names` 同时支持「整个文件夹」和「单个 txt 文件」两种配置。

## 6. 数据安全设计（重点）

这是整个项目最花心思的部分。

1. **原地配乐后撤回搬回来的是配乐版** —— 原因：`resolve_live_path` 在 `cur` 还存在时直接返回，没先查原片备份。现在优先用备份恢复，并把配乐成品作为待删项清理。改名模式配乐后撤回也一并修正（原来配乐边和重命名边是 `if/elif`，只能跟一条，会留下重复文件）。
2. **撤回一半失败会把整份日志作废** → 失败行另存成新日志，提示「关掉占用它的程序后再点撤回上次重试」。
3. **撤回时因原位置被占用而改名，用户完全不知情** → 完成提示里列出被改名的文件。
4. 撤回链的路径比较全部改用 `normcase`（Windows 大小写/斜杠不敏感，原来查不到已改名/已配乐的文件）。
5. 配乐日志里的 `CANCELLED` 行原来被当成有效迁移写进撤回链，会把文件判成「找不到」。
6. `unique_dest` 兜底名不再做存在性校验（同名会被 `os.rename` 静默覆盖），改为循环到确认不存在为止，并加进程内自增计数避免同一秒两次调用算出同一名字。

### 并发与状态

7. 两页原本各有各的 `_executing`，可以在同一个输出目录里同时分发 → 改为共用一个忙标志。
8. 撤回/重命名已分发没有忙守卫，可能和正在进行的分发/配乐抢同一批文件。
9. 所有子线程任务都加了异常兜底：任何未预料的异常都会恢复按钮/标志并明确告知（以前会让按钮永久禁用、之后所有操作被挡住）。
10. 任务进行中禁止切换页面（否则进度条和弹框跟着页面被隐藏）。

### 稳定性与边界

11. 子线程里读 Tk 变量 → 改为主线程先取值。
12. 配乐/改名日志写失败原来静默吞掉还告诉用户「可撤回」→ 改为明确警告撤不回。
13. 音乐库/命名库路径失效时不再偷偷把用户真实路径改成本地默认目录并写回配置，改为临时替代 + 状态栏提示。
14. 配置改为「先写临时文件再原子替换」。
15. 日期间隔填得过大不再 `timedelta` 溢出崩溃（夹在 10 年内并提示）。
16. `execute_move` 路径比较改 `normcase`；单个文件失败只记 `FAILED`，不中断整批。
17. 命名库改名时排序补了兜底 key，保证同一批文件每次分到的名字稳定一致。
18. 关窗时若任务在跑会先确认；清空素材时一并清掉旧计划和上次分发记录。

### Tkinter 布局踩坑

窗口变小时底部功能按钮「消失」，有两个独立的坑：

- `pack` 里控件不会小于自己的请求高度，且**前面的控件会把空间吃光**。表现为 `src_tree` 一次 `expand=True` 把同栏下面的按钮压成 1px、列表框被挤出面板外，看着像一条空缝。解法：改用 `grid` + 每张表各占一行、都带权重，剩余空间平分。
- 页面比容器矮时 Tk **不会裁剪**，而是让页面溢出到容器外盖住下方的音乐库栏。解法：窗口高度下限必须按两页真实需求的较大者 + 固定行高度计算，不能拍脑袋写死。代码里由 `_apply_min_size()` 在启动后自动完成。

## 8. 技术栈

- Python + Tkinter（`ttk` 表格）+ 可选 `tkinterdnd2`（拖拽）
- 打包：PyInstaller 单文件 exe，双击即用；ffmpeg 保持外置
- 日志 + 撤回：CSV 记录 `原路径 -> 新路径`
- 全流程离线，不调用任何在线服务
